# 上手引导

这份引导假设你从来没有搭过多智能体系统。每一步都写清楚要做什么，以及之后应该看到什么。看到的不一样，就停在那一步。

最快的路是对话式的：在 Claude Code 里打开项目并运行 `/zeuz-setup`。宙斯会自己完成安装，一次问一个问题，没有你的同意不做任何事。下面是同一条路，靠双脚走。

你需要 Bash 和 Node.js，还需要一个工作流宿主：一个执行流水线并给智能体提供工具的程序。Zeuz 不自带运行器，这一点写在这里，而不是让你以后才发现。

1. **把项目拿下来。**

   ```bash
   git clone https://github.com/zarubinvibe/zeuz.git
   cd zeuz
   ```

   你会看到 `zeuz` 目录，终端提示符进入其中。

2. **证明源码是完整的。**

   ```bash
   bash smoke/smoke.sh
   ```

   最后你会看到一行通过的闸门。它说明 Node 能解析这条流水线，可观测性、阶段图、闸门、schema、智能体和目录结构的必需标记都还在。这个过程不会调用任何智能体。

3. **明白你刚才检查了什么。** 这个检查故意是静态的：不花钱、不需要模型，却能抓住那种悄悄毁掉工厂的破坏。再往后的一切都需要宿主。

4. **告诉 Zeuz 把生成的项目放在哪里。**

   ```bash
   export ZEUZ_HOME="$PWD"
   export ZEUZ_PROJECTS="$PWD/../zeuz-output"
   ```

   生成的系统落在工厂之外，你的 diff 保持可读，也不会被意外覆盖。

5. **把流水线注册到你的宿主里。** `workflows/zeuz-pipeline.js` 需要宿主提供四样东西：输入、阶段标记、调用智能体和日志，并且支持结构化的智能体输出。

6. **写一份真正的规格。** 目标、输入、绝对不能跳过的完整性不变量、约束，以及怎样算做完。规格缺失或太短会被拒绝：没有完成标准，测试者无从检查。

7. **运行工厂，看着各个阶段走过去。** 观察阶段记录这台机器真实拥有什么；选角写下角色；架构排出阶段并在不可逆的步骤前放上闸门；省耗给每个阶段分配模型档位；构建写出文件；检验给出结论。

   你会在 `ZEUZ_PROJECTS` 下看到一个项目目录：智能体文件、工作流、协议、路由和计划图。

8. **读结论，别读摘要。** 只有测试者点头，这次运行才报告完成；否则返回需要修复，并附上问题清单。在你自己的检查通过之前，把生成的代码和说法都当作未经证实。

9. **先读，再信任。** 单独打开生成的项目，读它的闸门，跑它自己的测试，然后才允许它发布、归档、移动或部署任何东西。

## 如果这份引导帮到了你

如果 Zeuz 让你少一次从零发明闸门和日志，请点亮星标：[https://github.com/zarubinvibe/zeuz](https://github.com/zarubinvibe/zeuz)。这只要一秒，却决定别人能不能找到这个项目。

你已经从头到尾走过一遍，所以你正是能改进它的人。路径很短：先 fork 仓库，建一个分支 branch，提交 commit，推送 push，然后开一个 Pull Request。请不要直接向 `main` 推送，发布闸门会拒绝。

发现某一步写错了？到 [https://github.com/zarubinvibe/zeuz/issues](https://github.com/zarubinvibe/zeuz/issues) 开一个 issue，写清楚你运行了什么、看到了什么。
